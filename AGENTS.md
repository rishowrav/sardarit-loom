# AGENTS.md

Guidance for AI agents (and humans) continuing work on SardarIT Loom.

## What this is

A real, working single-user screen-recording app (personal Loom): owner login → record screen (720p / 1080p / 1080p+webcam) → chunked resumable upload to a private S3-compatible bucket (Backblaze B2 by default; Cloudflare R2 also supported) → library → token-based share links → quota cleanup. Not a demo — every feature is wired end to end.

## Commands

```bash
npm run dev                     # dev server
npm run lint                    # eslint — must pass (0 problems)
npx tsc --noEmit                # typecheck — must pass
npm test                        # unit tests (node:test via tsx) — must pass
npm run build                   # build; supply dummy env if none is set, e.g.:
# NEXT_PUBLIC_SUPABASE_URL=https://x.supabase.co NEXT_PUBLIC_SUPABASE_ANON_KEY=dummy \
# R2_ACCOUNT_ID=dummy R2_ACCESS_KEY_ID=dummy R2_SECRET_ACCESS_KEY=dummy R2_BUCKET=dummy \
# OWNER_EMAIL=owner@example.com npm run build
```

Run lint + typecheck + tests after any change; `npm run build` for anything touching routing/config. There are no real Supabase/R2 credentials in dev — never commit `.env.local`.

## Stack & hard-won environment facts

- Next.js **16.4** App Router (Turbopack), React **19.3**, TS strict, Tailwind 4, zod 4.
- **Auth gate is `src/proxy.ts`** (Next 16 renamed middleware → proxy). `middleware.ts` is deprecated here.
- Node 22 without native TS on this machine → tests run through `tsx` (`npm test` = `node --import tsx --test tests/*.test.ts`).
- `LayoutProps` in `src/app/layout.tsx` is generated by `next build` into `.next/types` — the standalone `tsc` run only passes *after* a successful build.
- `useSearchParams()` (login page) must sit under `<Suspense>` or the build fails.
- eslint-config-next ships **react-hooks/refs, set-state-in-effect, immutability** errors (React Compiler rules). Legit patterns used instead of disables:
  - external browser state → `useSyncExternalStore` (support check in `codecs.ts` with module cache; `document.hidden`),
  - prop-derived state → parent `key` (VideoPlayer keyed by `recording.id`),
  - fetch-on-mount → promise with `cancelled` flag in effect,
  - engine error handler → constructor arg, not post-hoc property writes.
  Prefer these patterns over `eslint-disable`.

## Architecture invariants (do not regress)

1. **No service-role key.** Everything DB runs as the signed-in owner under RLS. Public shares go through `SECURITY DEFINER get_shared_recording(p_token)` (created in `supabase/migrations/0001_init.sql`).
2. **Bucket stays private.** All object access via server-generated presigned URLs (`src/lib/r2.ts`), TTL from `PRESIGN_TTL_SECONDS` (default 6 h). Never make keys public. Store must support S3 multipart (B2 does: `s3.<region>.backblazeb2.com`, SigV4 presign ✓).
3. **Complete verifies with `ListParts`**, never client ETags; row only flips to `completed` after R2 size == DB `size_bytes`.
4. **Cleanup (`src/lib/storage-cleanup.ts`)**: pure `planCleanup()` (only when ≥ limit, oldest completed first, frees to 90%) + `runStorageCleanup()` (R2 delete first, DB delete only for fully-deleted rows; incomplete uploads never auto-deleted).
5. **Owner lock**: `OWNER_EMAIL` enforced in `src/proxy.ts` + `getOwnerContext()`.
6. **Single-owner proxy public paths**: `/login`, `/v/*`, `/api/share/*`, `/api/health` — everything else requires the owner session.
7. **Resumability**: upload sessions live in IndexedDB (`src/lib/upload/idb.ts`); blob written once, meta per part; stale multipart → `POST /api/uploads/[id]/reinit` (abort + recreate, same DB row).

## Conventions

- API routes: `force-dynamic`, `IdParams` from `@/lib/api` (`params: Promise<...>` — there is no global `RouteContext` type), errors via `jsonError`/`serverErrorMessage`, body validated with zod where input is non-trivial.
- Server-only env in `src/lib/env.ts` (`getServerEnv()` throws listing missing names; `envStatus()` for the settings page). Secrets never imported by client components.
- Client pages/components: `"use client"`, toasts via `useToast()`, classNames via `classNames()` helper.
- Icons: hand-rolled SVG components in `src/components/icons.tsx` (no icon package).
- Unit tests in `tests/*.test.ts` (node:test + `node:assert/strict`, `@/lib/...` paths work through tsx). Storage tests use dummy credentials — SigV4 signing is offline. `tests/r2-b2.test.ts` covers the B2 env shape (endpoint/region/path-style) in its own process because `getServerEnv()` memoises.
- README is the user-facing source of truth for Supabase/Backblaze B2 setup; keep `.env.example` and README's env table in sync.

## Gotchas when editing

- Changing chunking: keep ≥ 5 MB (R2 multipart minimum except final part) — enforced in `env.ts`.
- Recording stage machine: stop-from-browser relies on the engine's deferred result promise (`engine.result`) + phase subscription in RecorderStudio; don't make `stop()` await the result itself (deadlock risk).
- VideoPlayer resets `src` only via remount (`key`) or its own refresh endpoint — a prop-URL effect was removed on purpose (renames shouldn't restart playback).
- Don't add `cacheComponents`/next-font/google-fonts without checking build stability on this flaky network (deliberately removed).
